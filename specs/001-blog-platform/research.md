# Research: 개인 블로그 서비스 (MVP)

> 기술 결정과 근거를 모은다. 대부분 `docs/상세/*`의 `구현 방식`과 `docs/가이드/*`에서 이미 정한 것을 옮겼고,
> 원천 문서에 없어 이번에 고른 것은 **(새로 정함)** 으로 표시했다. 상태는 확정 / 가안 / 미정.

## R-01. 인증 방식: 서버 세션 (확정)

- **Decision**: 로그인하면 서버가 세션을 만들고 브라우저는 쿠키로 증명한다. JWT는 쓰지 않는다. 세션은 PostgreSQL(Spring Session JDBC)에 저장한다.
- **Rationale**: 즉시 로그아웃(FR-014), 다른 기기 끊기(FR-017, FR-021), 마지막 사용 후 7일 유지(FR-013)를 가장 단순하게 지킨다. 서버 1대라 토큰의 장점을 쓸 일이 없다. DB에 두면 서버를 다시 켜도 로그인이 유지된다.
- **Alternatives**: JWT + 재발급 토큰(끊을 목록을 결국 서버가 기억해야 함), Redis 세션(설치는 이미 하지만 세션까지 휘발성 저장소에 두지 않음).

## R-02. 세션 보호 설정 (가안)

- **Decision**: 쿠키 `HttpOnly`, `Secure`(배포 시), `SameSite=Lax`, 만료 7일 / 로그인 시 세션 ID 재발급 / Spring Security CSRF 토큰을 쿠키로 내려 주고 화면이 `X-XSRF-TOKEN` 헤더로 보냄 / 개발 중에는 Vite 프록시로 같은 주소처럼 사용.
- **Rationale**: NF-10~12. 같은 주소로 쓰면 CORS 설정이 필요 없다.
- **회원별 세션 찾기**: Spring Session JDBC의 principal name 색인(`FindByIndexNameSessionRepository`)으로 그 회원의 세션을 찾아 지운다.

## R-03. 비밀번호 저장과 규칙 (가안)

- **Decision**: BCrypt(강도 10~12). 규칙은 서버 정규식 `^(?=.*[A-Za-z])(?=.*\d)(?=.*[!@#$%^&*()_+\-=])[A-Za-z\d!@#$%^&*()_+\-=]{8,10}$`, 화면은 같은 규칙으로 바로 안내.
- **Note**: BCrypt는 72바이트까지만 쓰므로 길이를 20자로 늘려도 문제없다(spec Clarifications에서 8~10자 유지로 확정).

## R-04. 이메일 인증번호 저장 (확정: Redis)

- **Decision**: Redis 키에 용도를 붙여 구분한다. `(새로 정함)` 키 이름은 아래와 같다.

| 키 | 값 | 만료 | 용도 |
|---|---|---|---|
| `verify:{purpose}:{email}:code` | 인증번호 | 10분 | FR-006 |
| `verify:{purpose}:{email}:fail` | 틀린 횟수 | 인증번호와 같이 | 5회면 code 삭제 (FR-007) |
| `verify:{purpose}:{email}:cooldown` | 1 | 60초 | 1분에 1번 |
| `verify:{purpose}:{email}:daily` | 발송 횟수 | 첫 발송 후 24시간 | 하루 5번 |
| `verify:{purpose}:{email}:verified` | 1 | 30분 | 가입·변경 시 재확인 (FR-008) |

  `purpose`는 `signup` / `reset`. 이메일은 소문자로 바꿔 쓴다.
- **Rationale**: 만료와 1회용(맞으면 즉시 삭제)을 Redis가 자동으로 지킨다. 비밀번호 찾기는 같은 코드를 쓰고 DB 새 표가 없다.
- **비노출(FR-020)**: `reset` 용도는 가입 여부와 관계없이 cooldown·daily를 똑같이 올리고, 가입되지 않은 이메일은 code를 저장하지 않는다.
- **Redis 장애**: 인증번호를 보낼 수 없으므로 "잠시 뒤 다시 시도해 주세요"를 보여 준다.

## R-05. 인증번호 생성 (가안)

- **Decision**: `SecureRandom`으로 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`(32자) 중 6자리. (O, 0, I, 1 제외)

## R-06. 메일 발송 (가안 / 계정 미정)

- **Decision**: `MailSender` 인터페이스. 구현은 `SmtpMailSender`(Spring Mail, `@Async`)와 `LogMailSender`(개발용, 서버 로그에 인증번호 출력). 프로필로 고른다.
- **Rationale**: 개인 메일 계정의 하루 발송 한도를 개발 중에 아낀다. 계정(Gmail 앱 비밀번호 / 네이버 SMTP)은 미정.
- **발송 실패** `(새로 정함)`: 원천 문서는 `@Async`를 가안으로 적었지만, 비동기면 화면에 실패 문구(CF-01-18)를 바로 보여 줄 수 없다.
  그래서 **동기 호출 + 5초 시간 제한**으로 시작한다. 실패하면 code·cooldown 키를 지워 바로 다시 받을 수 있게 하고 실패 문구를 돌려준다.
  응답이 느려지면 비동기로 바꾸고 실패는 "다시 받기"로 안내한다.

## R-07. 로그인 실패 잠금 (가안)

- **Decision**: 회원 표에 `failed_login_count`, `locked_until` 칸. 성공·잠금 만료·비밀번호 찾기 변경 시 0으로. 비밀번호 변경·탈퇴의 현재 비밀번호 오입력도 같은 칸에 더한다. 없는 이메일은 기록하지 않는다.
- **Alternatives**: Redis 카운터(만료 자동). 영구 기록과 단순함을 위해 DB로 시작.

## R-08. 이미지 저장 (가안 / 배포 미정)

- **Decision**: `ImageStorage` 인터페이스 + `S3ImageStorage`(AWS SDK v2, MinIO 접속) / `DiskImageStorage`. 파일 이름은 서버가 UUID로 새로 만든다. 형식은 확장자가 아니라 **파일 앞부분(매직 넘버)** 으로 확인한다. 이미지는 서버를 거쳐 `/images/{key}`로 보여 주고 MinIO 포트는 바깥에 열지 않는다.
- **글과 연결**: 업로드 직후에는 글 없이 `post_image`에 기록(작성 중), 글 저장 시 본문에 들어 있는 이미지만 그 글에 연결한다. `(새로 정함)` 24시간이 지나도 글에 연결되지 않은 이미지는 매일 한 번 지운다.
- **Rationale**: MinIO 공개판은 2026-04 보관(archived)되어 교체 가능성을 열어 둔다(`docs/가이드/04`).

## R-09. 기본값 한 곳에 모으기 (가안)

- **Decision**: `application.yml`의 `blog.limits.*` 아래에 모든 숫자를 두고 `@ConfigurationProperties` 하나로 읽는다. 화면은 `GET /api/config/limits`로 같은 값을 받아 검사·안내에 쓴다. `(새로 정함)`
- **Rationale**: NF-08, 헌법 IV. 화면과 서버의 숫자가 어긋나지 않는다.

## R-10. 본문 형식과 스크립트 차단 (가안)

- **Decision**: 본문은 마크다운 글자로 저장한다. 화면에서 마크다운을 HTML로 바꾼 뒤 **허용 태그만 남기는 정화(sanitize)** 를 거쳐 보여 준다. 원시 HTML은 허용하지 않는다. 댓글은 마크다운 없이 글자 그대로(React 기본 이스케이프).
- **본문 글자 수(1~10,000자)**: 마크다운 원문 기준. 목록 미리보기 100자는 마크다운 기호를 뺀 글자 기준. `(새로 정함)`

## R-11. 검색 (가안)

- **Decision**: PostgreSQL `ILIKE '%단어%'`를 단어마다 AND로 묶는다. `%`, `_`, `\`는 이스케이프한다(FR-036, CF-11-9). 공개 글만, 작성 시각 내림차순.
- **확장**: 느려지면 `pg_trgm` GIN 색인을 단다. 한국어 형태소 검색은 범위 밖.

## R-12. 조회수·방문자 집계 (가안)

- **Decision**:
  - 방문자 구분값: 로그인 회원은 `m:{memberId}`, 비회원은 쿠키 `vid`(UUID, 1년)의 `v:{uuid}`. `(새로 정함: 쿠키 이름·기간)`
  - 조회수 중복 방지: Redis `view:{postId}:{visitorKey}` 30분 만료. 키가 없을 때만 +1.
  - 방문자 하루 1번: Redis `visit:{blogId}:{visitorKey}:{yyyyMMdd}` 한국 시간 자정까지 만료.
  - 블로그 주인 본인은 세지 않는다(spec Clarifications).
  - 기록: `daily_stats(blog_id, date)`에 `UPSERT ... view_count + 1`, `post.view_count + 1`. 느려지면 Redis에 모았다가 주기적으로 옮긴다.
  - 누적 숫자: `daily_stats`의 합으로 구한다(별도 누적 칸 없음). `(새로 정함)`
- **시간대**: 서버와 DB의 날짜 계산은 `Asia/Seoul` 기준으로 한다.

## R-13. 새 댓글 표시 (가안)

- **Decision**: `blog.comments_last_viewed_at` 칸. 새 댓글 = 그 시각 이후 + 작성자 ≠ 블로그 주인. 댓글 관리 화면을 열면 지금 시각으로 갱신. 처음(값 없음)에는 블로그 생성 시각을 쓴다.

## R-14. 탈퇴 처리 (가안)

- **Decision**: 한 트랜잭션으로 회원의 블로그(→ 분류, 글 → 글의 댓글·좋아요·태그 연결·이미지 기록·신고, 일별 통계)를 지우고, 회원이 남의 글에 단 댓글은 `author_id = NULL`로 바꾸고, 회원이 누른 좋아요와 한 신고를 지우고, 회원 행을 지운 뒤 모든 세션을 지운다. 이미지 파일은 트랜잭션 후 지운다.
- **재가입**: 회원 행을 실제로 지우므로 같은 이메일·닉네임으로 다시 가입할 수 있다(FR-019).
- `(새로 정함)` 탈퇴한 회원이 한 신고는 지운다(원천 문서는 언급 없음 — 신고는 처리 기능이 없어 남길 이유가 적다).

## R-15. 중복 제출 방지 (가안)

- **Decision**: 화면은 요청 중 버튼을 잠근다. 서버는 DB 유일 제약(이메일, 닉네임, 좋아요, 신고)으로 겹침을 막고, 댓글은 Redis `comment-cooldown:{memberId}` 5초 키로 막는다. 글 저장은 화면 잠금으로 충분하다고 본다.

## R-16. 테스트 전략 (가안)

- **Decision**: 헌법의 "자동 테스트로 확인" 대상(권한, 비공개 노출, 인증번호·잠금, 계정 비노출)은 Testcontainers 통합 테스트로 쓴다. 나머지 규칙은 서비스 단위 테스트. 화면은 비밀번호 실시간 안내 등 규칙 표시만 Vitest로 확인한다.
