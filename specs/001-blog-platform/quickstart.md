# Quickstart: 끝까지 동작하는지 확인하기

> 구현 후 사람이 직접(또는 통합 테스트로) 따라 하며 spec이 지켜졌는지 확인하는 시나리오다.
> 구현 코드나 설정 파일 내용은 넣지 않는다. API는 [contracts/api.md](contracts/api.md), 화면은 [contracts/screens.md](contracts/screens.md), 데이터는 [data-model.md](data-model.md)를 본다.

## 준비

1. Docker Desktop을 켜고 개발용 부품(PostgreSQL, Redis, MinIO)을 띄운다: `docker compose up -d` (`docs/가이드/03` 참고)
2. 서버를 `dev` 프로필로 실행한다. 메일은 실제로 보내지 않고 **서버 로그에 인증번호가 찍힌다**(research R-06).
3. 화면을 실행한다: `npm run dev` 후 브라우저에서 연다.
4. 브라우저 두 개(또는 일반 창 + 시크릿 창)를 준비한다. 아래에서 **A**는 글쓴이, **B**는 다른 회원, **V**는 로그인하지 않은 방문자다.

## 시나리오 A — 가입·로그인 (US1)

| # | 할 일 | 기대 결과 |
|---|---|---|
| A1 | A로 닉네임 `지영`, 새 이메일 입력 → `인증번호 받기` | 로그에 6자리 번호(O·0·I·1 없음), "인증번호를 보냈습니다…" |
| A2 | 곧바로 다시 받기 | "잠시 뒤에 다시 요청해 주세요" |
| A3 | 틀린 번호 → 맞는 번호 | "인증번호가 올바르지 않습니다" → "이메일 인증이 완료되었습니다", 이메일 칸 잠김 |
| A4 | 비밀번호 `abc12345`(특수문자 없음) | 특수문자 항목이 미충족으로 보이고 `가입하기` 비활성 |
| A5 | `abc123!@`로 가입 | 로그인 화면으로 이동. A의 블로그 "지영의 블로그"와 분류 "미분류"가 생김 |
| A6 | 같은 이메일로 다시 `인증번호 받기` | "이미 가입된 이메일입니다", 로그에 번호 없음 |
| A7 | 인증 없이 가입 API만 직접 호출 | `403` |
| A8 | 없는 이메일로 로그인, A 이메일 + 틀린 비밀번호로 로그인 | 두 경우 문구가 같다 |
| A9 | A 비밀번호를 5번 틀린 뒤 맞는 비밀번호 | 잠금 안내(남은 분), 로그인 안 됨 |
| A10 | B 계정도 같은 방법으로 만든다 | |

## 시나리오 B — 글쓰기·공개 범위·분류 (US2)

| # | 할 일 | 기대 결과 |
|---|---|---|
| B1 | A로 분류 "여행" 추가 → 글 "봄 여행 기록"(공개, 여행) 저장 | 상세 화면으로 이동, 작성 시각 표시 |
| B2 | 글 "비밀 일기"(비공개, 미분류) 저장 | A의 목록에 "비공개" 표시 |
| B3 | V로 A 블로그 목록·검색 "비밀"·"비밀 일기" 주소 | 목록·검색에 없음, 주소는 "존재하지 않는 글입니다" |
| B4 | B로 A 글의 수정 주소, 수정 API 직접 호출 | 화면 "존재하지 않는 글입니다", API `404` |
| B5 | A로 "여행" 분류 삭제 | "이 분류에 글이 1개 있어 삭제할 수 없습니다…" |
| B6 | "미분류" 삭제 | 삭제 불가 |
| B7 | B1 글을 아무것도 바꾸지 않고 저장 | 수정 시각이 생기지 않음 |

## 시나리오 C — 목록·검색 (US3)

| # | 할 일 | 기대 결과 |
|---|---|---|
| C1 | A로 공개 글을 모두 25개 이상 만든 뒤 V로 블로그 열기 | 최신순 10개, "N개의 글", 페이지 번호 |

## 시나리오 E — 계정·비밀번호 찾기 (US5)

| # | 할 일 | 기대 결과 |
|---|---|---|
| E1 | A를 두 브라우저에서 로그인 → 한쪽에서 비밀번호 변경 | 그 브라우저는 유지, 다른 쪽은 새로고침하면 로그아웃 |
| E2 | 로그아웃 후 비밀번호 찾기에 가입된 이메일과 가입 안 된 이메일 | 화면 안내가 똑같다. 로그에는 가입된 이메일 것만 번호가 찍힌다 |
| E3 | 인증 후 새 비밀번호로 변경 | 자동 로그인 없음, 모든 기기 로그아웃, 잠금 풀림 |
| E4 | B가 A 글에 댓글을 단 뒤 B 탈퇴 | B 블로그·글 사라짐, A 글의 B 댓글은 "탈퇴한 사용자" |
| E5 | B 이메일·닉네임으로 다시 가입 | 가입됨(새 계정) |

## 보안 점검 (헌법 II)

| # | 할 일 | 기대 결과 |
|---|---|---|
| S1 | 글 본문에 `<script>alert(1)</script>`, 마크다운 링크 `[x](javascript:alert(1))`, 댓글에 `<img src=x onerror=alert(1)>` | 어떤 스크립트도 실행되지 않는다 |
| S2 | CSRF 헤더 없이 글 삭제 API 호출 | `403` |
| S3 | 개발자 도구에서 `document.cookie` | 세션 쿠키가 보이지 않는다 |
| S4 | 로그인 전후 세션 쿠키 값 비교 | 값이 바뀐다 |
| S5 | DB에서 member 표 확인 | 비밀번호 원문이 없다. 서버 로그에도 없다 |
